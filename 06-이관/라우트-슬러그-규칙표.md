## 3. 슬러그 규칙

| 종류 | 규칙 | 예 |
|---|---|---|
| **Work** | `업종·기술 + 프로젝트명`, 한글 자연어 유지 | `커머스-리빙-리뉴얼` · `핀테크-결제-어드민` |
| **Insight** | `핵심 키워드 조합` | `바이브코딩-외주-고르는법` |
| **빌더** | 영문 소문자 이름 | `josh` · `minseo` |
| **금지** | 프로젝트명 단독(검색되지 않는다) · **고객사명 포함**(§14 Q7 — NDA·공개 동의 확인 전) | |

**한글 슬러그를 쓰는 이유**는 키워드가 URL 에 남기 때문이다. 브라우저 주소창에는 퍼센트
인코딩된 형태로 돌아다니지만 검색엔진은 디코드해서 읽는다.

> ⚠️ **한글 슬러그의 함정** — `generateStaticParams` 를 `dynamicParams = false` 와 함께 쓰면
> 없는 한글 주소가 404 가 아니라 **500** 으로 떨어진다(프리렌더 목록에 없는 인코딩 경로에서
> Next 가 `NoFallbackError` 를 던진다). 그래서 렌더까지 오게 두고 `notFound()` 로 직접
> 떨어뜨린다. `work/[slug]/page.tsx` 주석에 같은 내용이 있다 — **켜지 말 것.**

## 4. 301 정책 (SR-06)

**원칙: 발행된 슬러그는 바꾸지 않는다.** 바꾸면 공유된 링크와 GA4 이력이 함께 끊긴다.

그래도 바꿔야 한다면 **같은 커밋에 301 을 함께 넣는다.**

### 지금 — `next.config.mjs`

```js
{ source: '/work/옛-슬러그', destination: '/work/새-슬러그', statusCode: 301 },
```

`permanent: true` 를 쓰지 않는다 — 그건 308 을 내보낸다. 검색엔진은 308 도 영구 이동으로
읽지만 기획서가 요구한 코드는 301 이고 GET 문서 이동의 관례도 301 이라 `statusCode` 로
직접 지정한다.

현재 등록된 리다이렉트 2건 (목업 시절 단일 상세 라우트의 잔재):

| from | to | 이유 |
|---|---|---|
| `/work-detail` | `/work` | 1:1 대응하는 새 주소가 없다 — 구 주소가 보여주던 건 특정 프로젝트가 아니라 예시였다 |
| `/insight-detail` | `/insight` | 〃 |

### 어드민이 붙은 뒤 — `redirects` 테이블

```sql
redirects ( from_path text unique, to_path text, created_at timestamptz )
```

편집 화면에서 발행 후 슬러그를 바꾸면 **경고를 띄우고 이 테이블에 한 줄을 자동 생성**한다
(FR-A03-05). 미들웨어가 요청 경로를 이 테이블에서 조회해 301 을 낸다.

`archived` 로 내린 글도 404 가 아니라 **301** 로 보낸다(DR-08) — 목록으로 넘기면 색인 손실이
없다.
